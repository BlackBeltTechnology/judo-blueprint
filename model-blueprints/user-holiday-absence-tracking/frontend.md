## Overview

The user holiday/absence tracking pattern manifests in the React frontend through a custom card component for holiday display, dialog action hooks for the holiday input form with conflict detection, and a custom component implementation that replaces the default table for showing affected reservations during holiday creation.

## Implementation Pattern

- **Custom HolidayCard via CardsContainerConfigHook**: The default table rendering for holidays is replaced with a custom MUI Card component. A `CardsContainerConfigHook` is registered via Pandino for the HolidayPanel's holidays table, providing a `CardElement` that renders each holiday as a styled card with start/end dates, calendar icons, a decorative palm tree image, and a yellow accent bar at the bottom. The card includes a delete button gated by the `isNotDeletable` guard attribute with a confirmation dialog.
- **Dialog action hooks for HolidayInput form**: Pandino-registered `FormActionsHook` overrides provide: `onUserBlurAction`, `onStartDateBlurAction`, and `onEndDateBlurAction` that call `hideReservationsForDeleteInfo` to dynamically query and display affected reservations when the user changes the holiday's user, start date, or end date; `postGetTemplateAction` that initializes the user selector visibility based on admin status; `getStartDateValidationProps` and `getEndDateValidationProps` that enforce minimum date constraints (no past dates).
- **Custom component for reservationsForDeleteInfo**: A `CUSTOM_VISUAL_ELEMENT_INTERFACE_KEY` Pandino service replaces the default rendering of the `reservationsForDeleteInfo` relation on the HolidayInput form. It uses an `EagerTable` component with custom columns (date, startTime, endTime, reservationType, reserver name, parking slot info, owner) to show which reservations will be affected by the new holiday. This enables users to see the impact of their holiday before confirming.
- **Shared service utility module**: Business logic is extracted into `custom/services/HolidayInputServices.ts` with functions like `hideReservationsForDeleteInfo` (queries the backend `queryReservationsForHoliday` operation to fetch colliding reservations and updates the form via `storeDiff`), `holidayInputPostGetTemplateAction` (hides user selector for non-admin users), and date validation functions.
- **Dual context registration**: Holiday input hooks are registered for both the standalone HolidayPanel context and the ReservationsPanel context (which also allows holiday creation), sharing the same `HolidayInputServices.ts` utility functions.
- **i18n**: Hungarian translations cover holiday form field labels, the DayType enum members (WORK, HOLIDAY), confirmation messages for holiday deletion, and table column headers for the affected reservations display.

## Examples

### park-here
- Framework: React
- Key files: `custom/hooks/components/HolidayCard.tsx`, `custom/hooks/components/cards/registerServicesHolidayPanelHolidayPanel_View_EditHolidaysComponentConfigurationHook.tsx`, `custom/hooks/dialogs/registerServicesHolidayPanelHolidayPanel_View_EditHolidayInputFormActionsHook.ts`, `custom/hooks/dialogs/registerServicesReservationsPanelReservationsPanel_View_EditHolidayInputFormActionsHook.ts`, `custom/hooks/custom-implementations/registerServicesHolidayInputHolidayInput_FormCustomImplementations.tsx`, `custom/services/HolidayInputServices.ts`
- Pattern: Holidays are rendered as styled cards with palm tree imagery and calendar icons. The holiday creation form dynamically queries colliding reservations when user/dates change, displaying them in a custom EagerTable. The `hideReservationsForDeleteInfo` function calls `servicesUserForInputServiceImpl.queryReservationsForHoliday()` to fetch affected reservations and populates the form's `reservationsForDeleteInfo` field. The user selector is hidden for non-admin users via `postGetTemplateAction`.
- Notable: The custom component implementation (`registerServicesHolidayInputHolidayInput_FormCustomImplementations.tsx`) is one of the more advanced patterns -- it replaces an entire table component using `CUSTOM_VISUAL_ELEMENT_INTERFACE_KEY` rather than just customizing behavior via action hooks. The affected reservations table includes columns for reservation type (with i18n-translated enum values), owner, and parking slot info, giving users full visibility into the impact of their holiday before submission.
