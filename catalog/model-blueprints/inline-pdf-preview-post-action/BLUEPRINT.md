## Intent

When a backend operation generates a PDF, the user usually wants to see it at once. The default behaviour shows the operation output in a generic view dialog. This pattern replaces that step for a document-generation operation: the input dialog closes, and the PDF opens in a browser tab in inline mode.

### The hook decides what happens after the operation

A dialog form action hook receives the operation output. The hook closes the input dialog and passes the file token to the generated `fileHandling.downloadFile` helper. The default output view is not shown. The hook itself is common practice on top of the platform: the platform generates the dialog action hook scaffold and the download helper, and the inline use is the application's choice.

### The file token can take two shapes

The output carries the file either as a string token or as an object with an identifier. The hook accepts both.

## Structure

The pattern is a frontend element only. A dialog form action hook for the operation receives the output, closes the input dialog, extracts the file token, and calls the generated `downloadFile` helper with the inline disposition. The helper wraps the platform's token-gated download: the file is fetched from the download path with `?disposition=inline` and the `X-Token` header. No model element is added. The operation that produces the PDF is an ordinary custom operation that returns a file.

## Constraints

- The hook runs only after the backend operation has returned successfully.
- The input dialog is closed before the PDF is opened, so the dialog does not stay open behind the viewer.
- The file token is resolved by the generated `downloadFile` helper. The hook does not build URLs or send the token itself.
- Errors from opening the file are caught and logged. The dialog is still closed.
- The hook key is generated for the dialog. A `register<Dialog>ActionsHook.ts.default` scaffold exists only when the action hook is enabled in the model. Use the generated name, not a name copied from another page.

## Variations

- **Preview only.** The hook opens the PDF inline and does not store anything else.
- **Preview plus download.** The hook opens the PDF inline and also offers a download control on the same page.
- **Per document type.** One hook per document operation, each with its own name, for example one for an assessment sheet and one for a review report.

## When to use

- A generated PDF is for review, and the user needs to see it immediately.
- The document is generated by a custom operation that returns a file.
- The page already has a dialog form for the operation.

## When to avoid

- The document must be stored and handled later, not just viewed. Use the default output view or a download.
- The operation produces many files at once. A single inline tab is the wrong pattern.
- The UI is generated without customization and the default output view is acceptable.
