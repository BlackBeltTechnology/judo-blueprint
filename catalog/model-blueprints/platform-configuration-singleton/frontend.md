## Overview

The frontend shows the Configuration row to administrators and lets them edit it. The update form should open with the current values already filled in, so the user does not face an empty form.

## Implementation Pattern

- **Pre-fill the update form.** When the update form template loads, a hook fetches the current configuration with a mask that covers every editable field, then writes each value into the form. Only fields that have a value are written.
- **Field-by-field fill.** Iterate over the editable fields and set each one separately, so an empty optional template does not overwrite a default.
- **No create or delete.** With createable and deleteable false, the generated UI shows no create or delete action; hide any leftover entry points, since the row is seeded once.

Hook and form names are generated by the framework and differ per project; the pattern is what matters.

## Examples

- Framework: React.
- The hook fetches the admin configuration transfer object with a mask over nine fields, then pre-fills the input form field by field. This is needed because the input transfer object differs from the mapped transfer object.

- The configuration page edits business parameters and document templates. Binary template fields are edited as uploads, not as text.

- The configuration form edits the sender address, the contact address and the notification templates.

The hook and service names in these examples are project code, not platform classes.
