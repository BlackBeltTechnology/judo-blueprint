A modeled fault is a transfer object type in the ESM/JSL model that is attached to an operation as a fault (`<faults>` in the ESM model; `error` declarations with a `throws` clause in JSL).

- The SDK generator turns each fault into a checked `<Fault>Exception extends java.lang.Exception` with typed details and the constructors `(details)`, `(errorCode, details)` and `(errorCode, details, cause)`. The error code is the exception message.
- The operation must **declare the fault**. If a custom-implemented operation has no declared fault, the generated SDK interface has no `throws` clause and Maven fails with `... not compatible with throws clause` when you throw one.

### Variable Providers

A derived attribute that adds up a field over a collection must behave well when some items have no value in that field, or when the collection is empty. Make the null handling explicit in the expression.

## Practice

### Choose the guard by the field's cardinality

This is project practice on top of the platform's collection functions. The platform (see [model development, collection functions](../../agent-docs/model/model-development.md)) provides `!filter`, `!isDefined()`, `!count()`, `!sum`, `!avg`, `!min`, `!max` and the ternary `cond ? a : b`. It does not document how an undefined selector value or an empty collection is treated by `!sum`, so the practice does not rely on either.

- **Required field**: sum it directly, `self.lines!sum(l | l.amount)`.
- **Optional field**: filter first, `self.lines!filter(l | l.discount!isDefined())!sum(l | l.discount)`.
- **Possibly empty collection**: guard with the ternary, `self.lines!count() > 0 ? self.lines!sum(l | l.amount) : 0`. Both branches must have the same kind (the platform requires the same kind for then and else).

### Know the limits of the aggregates

`!sum` accepts integer and decimal selectors only; other types fail with `Invalid expression for aggregation`. `!avg`, `!min` and `!max` take the same selector form, so the same filter-first shape applies to them. Keep each lambda to one iteration variable: lambdas do not nest and cannot see `self`.

Three distinct places an operation can surface in the UI:

```mermaid
flowchart LR
  O["operation::Operation<br/>on TransferObjectType"]
  OF["ui:OperationForm<br/>(widget / button)"]
  TO["ui:TableOperation<br/>(row / table action)"]
  MIO["ui:MenuItemOperation<br/>(menu entry)"]
  O -->|name| OF
  O -->|xmi:id| TO
  O -->|targetOperation| MIO
  TO -->|operationForm<br/>(nested)| OF
```

| Placement | When to use |
|---|---|
| `OperationForm` inside View/Form/Group | The operation sits inline in a page or dialog |
| `OperationForm` inside `ActionGroup` | Grouping related operations with an overflow menu |
| `TableOperation.operationForm` inside `rowOperations` | Per-row action (single record context) |
| `TableOperation.operationForm` inside `tableOperations` | Toolbar action (collection or selection context); set `isBulk=true` for multi-select |
| `MenuItemOperation` on ActorType | Static/global operation triggered from the top-level menu |

`confirmationType` on `OperationForm` controls dialogs:
- `NONE` — no confirmation
- `CONDITIONAL` — `confirmationCondition` (boolean `DataMember`) decides
- `MANDATORY` — always confirm, set `confirmationMessage`
