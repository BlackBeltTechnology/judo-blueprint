The two data-migration changesets (`updateDataBeforeIncremental` and `updateDataAfterIncremental`) are generated empty, and you write them when the change needs data work ([schema evolution, manual scripts](../../agent-docs/deployment/schema-evolution.md#step-3-manual-migration-scripts-optional)). `schema-upgrade` generates and applies in one step, so it leaves no point to edit these changesets; for a backfill, run generate, edit the changeset, then execute separately ([build process, command reference](../../agent-docs/deployment/build-process.md#command-reference)).
- Entity tables are named `T_ENTITIES_<NAME>` and columns `C_<NAME>`. Check the generated changelog for the exact names (same guide).
- Generation overwrites the files of the output folder except review files, so confirm against the guide that a hand-written changeset survives regenerating the folder, and re-check it after every regeneration (*verify*).

### Building Docker Image

The build process creates Docker image tars when Docker building is requested:

```bash
./judo.sh build -d
```

Image details (jib, base image, tags, agents, ports) are in [Build Process](./build-process.md#docker-image-build).

**Output:**
- Docker context: `/application/docker/target/docker/`
- Docker image: Tagged with project version

### Docker Image Contents

The Docker image includes:
- Karaf standalone distribution
- All OSGi bundles
- Configuration files
- Runtime dependencies

### Running Docker Container

**Basic deployment:**
```bash
docker run -d \
  --name <app>-app \
  -p 8181:8181 \
  -e JUDO_PLATFORM_RDBMS_DIALECT=postgresql \
  -e JUDO_PLATFORM_RDBMS_DB_HOST=postgres \
  -e JUDO_PLATFORM_RDBMS_DB_PORT=5432 \
  -e JUDO_PLATFORM_RDBMS_DB_DATABASE=<app> \
  -e JUDO_PLATFORM_RDBMS_DB_USER=<app> \
  -e JUDO_PLATFORM_RDBMS_DB_PASSWORD=yourpassword \
  -e JUDO_PLATFORM_KEYCLOAK_AUTH_SERVER_URL=http://auth:8080 \
  -e JUDO_PLATFORM_IDENTIFIER_SIGNER_SECRET=<stable base64 secret> \
  <image>:<tag>
```

The image tag comes from `DOCKER_IMAGE_TAGS` (default `dev`). All variables are described in [Application Configuration](./application-config.md).

  await d.getByRole('button', { name: /(Ok|Submit)$/ }).click();
  const number = field(page, /^Number/);
  const ok = await number.waitFor({ timeout: 20000 }).then(() => true).catch(() => false);
  if (!ok) return null;

}
